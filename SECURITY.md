# Security reporting

## Report privately

Please email **[support@anhbui.dev](mailto:support@anhbui.dev)** with the subject **Claude Export security report** for a suspected vulnerability affecting the extension or its official service.

**Do not disclose exploitable vulnerabilities, proof-of-concept payloads, credentials or affected customer information in public issues, discussions or pull requests.** This policy uses private email; it does not assume GitHub private vulnerability reporting is enabled.

## What to include

- A concise description and the affected product version/browser.
- Reproduction steps using a test account and synthetic, non-sensitive content.
- Expected behavior, observed behavior and likely impact.
- A way to contact you privately for follow-up.

Never send real user conversations, payment details, license or integration tokens, passwords or verification codes. If sensitive material seems necessary, explain why first and agree a suitable private handling method with support.

## Responsible testing and disclosure

Test only on accounts, devices and data you own or are authorized to use. Do not access another person's data, disrupt service, run destructive tests or use social engineering. Stop when you have enough evidence to describe the issue.

Please allow reasonable time for private investigation and remediation, and coordinate public disclosure with the maintainer. Support will discuss next steps privately; this policy does not promise a response deadline, bounty, legal safe harbor or reward.

## Versions and updates

Use the latest version offered by your browser's official store. Include the actual installed version in reports: scheduled website releases may not yet be published. See the [changelog](CHANGELOG.md) and [installation guide](docs/installation.md). This policy does not promise maintenance of every historical version.
